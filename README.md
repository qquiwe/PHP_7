## Висновок
**N+1 у списку транзакцій виконує окремий
SELECT SUM(amount) ... WHERE category = ... для кожного рядка результату,
тому час і кількість запитів ростуть лінійно з кількістю транзакцій; заміна
цього на один агрегатний запит GROUP BY category прибирає цю залежність і
тримає кількість запитів сталою (2), а кешування balance() додатково
уникає повторного підрахунку SUM(amount) по всій таблиці на кожен запит,
поки дані не змінилися.**
**На малій тестовій таблиці N+1 не дає помітної різниці в часі через накладні витрати самого `php -S`, тому головним доказом оптимізації є не `ab`, а різниця в `X-Query-Count`** (1+N проти сталих 2 запитів).
